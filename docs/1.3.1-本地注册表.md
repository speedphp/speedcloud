# speed 1.3.1：本地注册表与基础 API

> 本章教程配套 speed 1.3.1（9 模块之①注册中心的第二个 patch）。阅读前提：speed 1.3.0（脚手架与项目骨架，见 `docs/教程.md`）。
>
> 配套代码：本仓库 `src/registry/`；可运行验证：`npm test`（`test/registry.test.ts`）。

---

## 一、为什么：先有「单点真相」，再有服务发现

注册中心（对标 Eureka / Nacos Discovery）要回答一个最朴素的问题：**「哪个服务现在跑在哪个地址上」**。这个问题的答案，就存在一张表里——这张表就是**注册表**。

speed 把注册表定为整个注册中心的「单点真相」：后续所有能力（`@Service` 自动注册、心跳、摘除、服务发现、变更监听）都读写它。所以 1.3.1 的目标非常克制，只做三件事：

1. **数据结构**——服务名 → 实例列表的两级 Map，一次设计对；
2. **三个基础 API**——`register`（注册）、`unregister`（注销）、`getInstances`（查询）；
3. **去重语义**——同一服务内，同 `host:port` 的实例重复注册只更新、不新增。

这一层**不涉及网络协议**，是纯内存操作。先把单机闭环跑通，1.3.8 再接 Nacos（opt-in，不破坏已有行为）。

## 二、怎么用：三行代码注册一个实例

### 2.1 引入

注册表通过子路径导出，从 `speed/registry`（或主入口 `speed`）引入：

```ts
import { LocalRegistry, ServiceInstance } from "speed/registry";
```

### 2.2 注册 → 查询 → 注销

```ts
const registry = new LocalRegistry();

// 注册：一个服务名可以挂多个实例（负载均衡的基础）
registry.register("user-service", { host: "127.0.0.1", port: 8080 });
registry.register("user-service", { host: "127.0.0.1", port: 8081, metadata: { version: "v2" } });

// 查询：拿到该服务的全部实例
const instances = registry.getInstances("user-service");
// => [ { host: "127.0.0.1", port: 8080, registeredAt: 1725792000000 },
//      { host: "127.0.0.1", port: 8081, registeredAt: ..., metadata: { version: "v2" } } ]

// 注销：按 host + port 精确移除
registry.unregister("user-service", "127.0.0.1", 8080); // true
```

### 2.3 去重：重复注册只更新

同一服务内再次注册相同 `host:port`，**不会产生第二条记录**——只原地刷新注册时间、更新元数据：

```ts
registry.register("user-service", { host: "127.0.0.1", port: 8080 });
registry.register("user-service", { host: "127.0.0.1", port: 8080, metadata: { version: "v2" } });

registry.getInstanceCount("user-service"); // 1（不是 2）
registry.getInstances("user-service")[0].metadata; // { version: "v2" }
```

> 区分：**同名多实例是正常的**（`host:port` 不同），**同 `host:port` 才是重复**。前者是负载均衡的基础，后者会被去重。

## 三、原理：一张两级 Map 走到底

### 3.1 数据结构

注册表内部只有一张表：

```ts
private instances = new Map<string, ServiceInstance[]>();
//                      ^服务名          ^该服务的实例列表
```

两级结构：**服务名 → 实例列表**。每个实例是一个 `ServiceInstance`：

```ts
export interface ServiceInstance {
    host: string;
    port: number;
    registeredAt?: number;              // 注册时间戳，register 时自动填充
    metadata?: Record<string, unknown>; // 元数据扩展位（1.3.6 起承载 version/weight/tags）
}
```

两个设计点值得说明：

- **`host:port` 是实例唯一标识**——同一服务内靠它去重与定位，不额外引入实例 id；
- **`metadata` 是预留的扩展位**——1.3.6 会用它承载版本、权重、灰度标签，现在先把字段占好，避免后面改结构。

### 3.2 去重怎么做

`register` 里以 `${host}:${port}` 为键做**线性查找**：实例列表规模通常很小（一个服务几个实例），线性查找足够，换来的是结构简单、无额外索引。命中旧实例就原地刷新，未命中就补全 `registeredAt` 后 push。

```ts
register(serviceName: string, instance: ServiceInstance): ServiceInstance {
    const key = `${instance.host}:${instance.port}`;
    const list = this.instances.get(serviceName);
    if (list) {
        const existing = list.find((item) => `${item.host}:${item.port}` === key);
        if (existing) {
            existing.registeredAt = Date.now();               // 刷新（心跳语义）
            if (instance.metadata !== undefined) existing.metadata = instance.metadata;
            return existing;
        }
        // ...
    }
    // ...
}
```

### 3.3 读路径返回拷贝

`getInstances` 返回的是**浅拷贝**（`[...list]`），而不是内部数组引用。这样外部怎么改返回结果，都不会污染注册表的内部状态——注册表是「单点真相」，不能让调用方碰坏它。

```ts
getInstances(serviceName: string): ServiceInstance[] {
    const list = this.instances.get(serviceName);
    return list ? [...list] : [];
}
```

### 3.4 注销后清理空服务

`unregister` 移除实例后，若该服务的实例列表已经空了，会顺手把「服务名」这个 key 从 Map 里删掉——保证 `getServiceNames()` 反映的永远是「当前还活着的服务」。

## 四、怎么扩展：从这里走向 `@Service`

1.3.1 只交付了「手写的注册表」。接下来每个 patch 都在它之上叠一层，且都不需要改它的结构：

| patch | 内容 | 与注册表的关系 |
|---|---|---|
| 1.3.2 | `@Service` 装饰器 | 类「声明即注册」，自动调用 `register()` |
| 1.3.3 | 心跳 | 定时刷新实例时间戳（给 `ServiceInstance` 加 `lastHeartbeat`） |
| 1.3.4 | 健康检查 + 超时摘除 | 扫描注册表，超时实例调 `unregister()` |
| 1.3.5 | 服务发现 | 封装 `getInstances()` 并做健康过滤 |
| 1.3.6 | 实例元数据 | 填满 `metadata` 字段，供 LB/网关读 |
| 1.3.7 | 变更监听 | 注册/注销时触发订阅方回调 |
| 1.3.8 | Nacos 适配 | 把 `LocalRegistry` 抽象成 `Registry` 接口，加 Nacos 实现 |

**给贡献者的扩展点**：

- 新能力优先挂在 `LocalRegistry` 的方法上，别绕过它直接碰内部 Map；
- 1.3.8 做「接口先行」时，`register` / `unregister` / `getInstances` 就是现成的接口签名；
- 元数据语义（`version` / `weight` / `tags`）在 1.3.6 统一定义，现在不要在 `metadata` 里塞私有字段。
